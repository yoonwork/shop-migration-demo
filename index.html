옛 주문 파일

킴스몰 주문을 내려받은 CSV라고 가정했어요. 칸 이름은 예시예요(실제 구조는 DB를 받은 뒤 확인).

    
        
    
      
    

      
      
    
        
    칸 맞추기
    옛 칸을 퍼스트몰 주문 항목에 하나씩 연결해요. DB 칸 이름은 공개 자료에 없어서 전부 예시예요.
    
        
    
          
    옛 칸퍼스트몰 쪽 항목DB 칸바꾸는 방법
    
          
        
    

        
    상태값 변환표 퍼스트몰 주문 단계는 공식 구축 가이드 기준
    
        
    
          
    옛 상태주문 수퍼스트몰 단계메모
    
          
        
    
        
    주문접수 → 결제확인 → 상품준비 → 출고준비 → 출고완료 → 배송중 → 배송완료가 퍼스트몰 기본 단계예요. 공식 이전 서비스는 취소·반품·환불 주문을 옮기지 않아서, 기록 보존용으로 '취소', '반품·환불'로 따로 남겨요.
    

        
    보완 규칙 1차에서 걸린 주문을 어떻게 옮길지 정해요
    
        
    
      
    

      
      
    
        
    
          
    변환 미리보기
    
        
    
        
    
        
    
          
          
    옛 주문번호 · 주문일주문자 · 회원상품결제금액퍼스트몰 단계결과
    
          
        
    
        
    이 조건에 맞는 주문이 없어요.

    리허설 보고서
    클라이언트께 회차마다 이 내용과 대조표 파일을 드려요.
    
          
    
            
            
          
    
        
    
        
    
        
    
          
    
            
    조회 화면 확인
    
            
    옮긴 주문이 회원 마이페이지에서 어떻게 보이는지 회원을 골라 확인해요. 옛 주문번호를 그대로 보여 줘서 고객 문의 때 바로 찾을 수 있어요.
    
            
            
            
    조회 방식 두 가지 데이터를 보고 미팅에서 정해요
    
            
    
              
    퍼스트몰 주문 목록에 넣기
    옛 주문을 퍼스트몰 주문 테이블에 '배송완료' 등으로 넣어요. 관리자 주문 목록과 마이페이지에 그대로 섞여 보여요. 공식 유상 이전과 같은 방식이고, 출고 기록이 없어 반품·환불은 손으로 처리해요.
    
              
    따로 보관하고 조회 화면 만들기
    옛 주문을 별도 보관 테이블에 넣고 마이페이지·관리자에 '지난 쇼핑몰 주문' 화면을 붙여요. 퍼스트몰 패치가 주문 테이블을 바꿔도 영향이 없어요. 오른쪽이 이 방식의 예시예요.

      패치 반영 기록
      
      
      커스텀한 독립형 쇼핑몰에 쌓인 공식 패치를 한 회차로 반영하는 순서예요. 덮어쓰기 전에 우리 파일과 겹치는 곳을 먼저 찾고, 시험 서버에서 결제까지 확인한 뒤 본 서버에 올려요.
      
    
      
  
      

  
      
    
      
      
      
        
      
          
      이번 회차 패치
      독립 일반몰 공개 패치 리스트, 2026.08.13 ~ 10.14 (스킨 파일은 PC·모바일 기본 스킨만)
      
        
      
        
      
        
      
          
      포함번호날짜제목영역파일
      
          
        
      
        
      출처: 퍼스트몰 패치리스트 · 2026-10-22에 확인 · 수정파일 내려받기와 소스설명보기는 로그인이 필요해요.
      
      
      

      
      
        
      겹치는 파일
      패치 파일 목록과 우리 커스텀 목록(git 기록)을 맞대 보고 나눠요. 커스텀 목록은 가상이에요.
      
        
      
      
      

      
      
        
      
          
      백업
      반영 전에 소스와 DB를 따로 받아 두고, git에 '반영 전' 표시를 남겨요.
      
          
      
        
      
        
      아직 백업하지 않았어요.
      
      
      

      
      
        
      
          
      시험 서버 반영
      본 서버를 복사한 시험 서버에 먼저 올려요. DB 패치는 오래된 것부터 차례로 돌려요.
      
          
      
        
      
        
      백업을 마친 뒤에 할 수 있어요.
      
      
      

      
      
        
      
          
      주요 기능 점검표
      상태를 눌러 바꿀 수 있어요. 시험 서버가 모두 '통과'여야 본 서버에 올려요.
      
          
      
        
      
        
      
          
      확인할 것구분시험 서버본 서버
      
          
        
      
      
      

      
      
        
      
          
      본 서버 반영
      주문이 가장 적은 시간에 점검 화면을 켜고, 시험 서버와 같은 코드를 올려요.
      
          
      
        
      
        
      시험 서버 점검이 모두 통과해야 할 수 있어요.
      
      
      

      
      
        
      
          
      되돌리기 방법
      본 서버 점검에서 주문·결제가 하나라도 안 되면 바로 이 순서로 되돌려요. 걸리는 시간은 예시예요.
      
          
      
        
      
        
        
          
      1. 소스 · 약 10분
        git에 남긴 반영 전 표시 before-2026q4로 되돌린 뒤, 이번에 바뀐 파일만 FTP로 다시 올려요. 백업 압축 파일도 함께 있어요.
        2. 
          
      2. DB · 약 15분
        DB 패치가 있던 회차라 반영 전 덤프로 복원해요. 반영 뒤 들어온 주문이 있으면 먼저 따로 뽑아 두고, 복원한 다음 다시 넣어요.
        3. 
          
      3. 확인
        점검표를 본 서버 기준으로 다시 돌리고, 결제사 관리자 화면에서 시험 결제 취소까지 확인해요.
        4. 
          
      4. 기록
        무엇 때문에 되돌렸는지 남기고, 시험 서버에서 고친 뒤 날을 다시 잡아요.
